## Insights for automation

- **`fill()` does not trigger elFinder's incremental search** — the search input at `.elfinder-button-search input[type="text"]` needs real keystroke events (Playwright's `pressSequentially()`), not a bare `.fill()`, to actually filter the grid. A `.fill()` followed by `Enter` silently left the grid unfiltered in this session's first attempt.
- **elFinder toolbar buttons are `[title="..."]` divs**, not semantic buttons — `page.locator('[title="Go to parent folder"]')`, `[title="Delete"]`, `[title="List view"]`, etc. work reliably. The status bar's live item count/size is most reliably read from `.elfinder-stat-size`'s `title` attribute (e.g. `"Items: 2,&nbsp;Sum: 517 KB"`), not its rendered text, since the rendered text is split across child spans.
- **The elFinder folder tree encodes paths as a custom base64-ish node ID** (e.g. `nav-A_dXBsb2FkL2NhbmRpZGF0ZS8zMjc0L2N2` decodes to `upload/candidate/3274/cv`) — useful if automation ever needs to assert tree structure programmatically rather than by visible label text.
- **The "Set interview" and "Interview result" dialogs' Cancel/Save buttons can render outside a default/small viewport** in headless runs, causing `locator.click()` to time out with "element is outside of the viewport" even though the dialog itself is open and correct — real test code should either scroll the dialog's button into view explicitly or use a taller viewport, rather than assuming a plain `.click()` will always land.
- **The candidate list's row count has dropped from 27 (when `specs/candidate-management.md` was authored, 2026-08-06) to 15 as of this session (2026-08-24)** — some previously-referenced real candidates (e.g. Julie MARTIN, Sunny QA, Ranny QA, Windy QA, Kim MOUY, Sovan NI, SreyNeang PHEAK, Thida PICH, Pheakkdey MUT, Tita SAN — some of which still show up here as real rows, others may have been archived) may no longer exist or may have moved. Any future automation that hardcodes a candidate ID or count from an older exploration session should re-verify it still exists rather than assuming stability across sessions on this shared dev environment.
- **An "Experience" card can appear between the profile card and the Education card** for candidates with logged internship/experience data (observed on Sopheak PHAL: Position, Level, Start Date, End Date, Project Type, each following the same `text-label`/`text-value` pattern) — not covered by any of the 10 user stories in scope for this plan, but automation that blindly queries all `.text-label` elements on the page (as this session's own scripts did) will pick up these fields too and should scope more narrowly (e.g. within a specific card container) if it needs to assert only the profile card's fields.
